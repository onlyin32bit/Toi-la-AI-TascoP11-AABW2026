G2 · Appendix A2 · Full architecture

S0 → S7: offline enrichment is decoupled from online serving

Left = runs offline (agent, spends API credits). Right = online (single binary, cache-first, survives dead wifi).

This is the answer to the Q&A "scraping legality" and "how does Tasco integrate": enrichment runs offline, the query path never calls a scraper, and serving matches Tasco's contract exactly. One binary + one KB file = integration is pointing their gateway at our endpoint.

G4 · Appendix A3 · Trust model

5-tier cascade: a fact is only written if it wins a contest between sources

Every field is an auction between candidates. Highest tier wins · lower tiers need N≥3 consensus · signals never compete.

This diagram answers "data quality of scraped facts": no single scraped source ever becomes a published fact alone. The duel example shows Tasco's driver data outranking every public source — that's the moat living inside the mechanism, not just on a slide.
G5 · Appendix A6 · Ranking model

SOFT score: Σ wᵢ·Sᵢ — 0.35 of total weight comes from signals only Tasco can generate

7 components, sum to 1.00. Missing data → drop the component + renormalize, never fake a 0.5.

S_match is multiplied by confidence from the resolver: parking confirmed by a driver (0.85) contributes more than an agentic guess (0.60) — ranking inherits the cascade's trust. No other Vietnamese system does this.
G6 · Appendix A1 · When the system runs itself

6 triggers: a living system, not a dead dataset

This is the literal meaning of "continuously enriched" in the brief.

T2 (gap-detect) is the demo hero: RES019–030 jump quality 0.6 → 0.9 live on stage. T4/T5 run simulated and badged, never feed the benchmark.
